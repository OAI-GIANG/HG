# ADR-006 — Reconcile Before Retrying Uncertain Actions

- Status: Proposed
- Context: Timeouts can occur after a side effect has succeeded, making blind retries unsafe.
- Decision: Mark uncertain outcomes UNKNOWN, inspect live state, evaluate idempotency and retry policy, and only then choose replay, recovery or hold.
- Alternatives: Retry every timeout; treat timeout as failure; rely only on process exit codes.
- Consequences: Prevents duplicate non-idempotent actions but requires recovery adapters and bounded waiting.
- Rules: MAEP-014, 016, 018, 025, 027.
- Acceptance evidence: Simulated timeout-after-effect tests and restart reconciliation tests. Not yet implemented.
